# 挑战与成就规格

## Purpose

定义挑战浏览、参与、进度计算、徽章和演示排行榜行为。

## Requirements

### Requirement: 挑战浏览与参与

系统 MUST 展示至少 60 个具有稳定标识的本地挑战，按运动类别、目标和难度层级浏览，并展示精选挑战、目标、剩余时间和参与状态；系统必须允许用户加入尚未结束的挑战。

#### Scenario: 加入挑战
- **WHEN** 用户点击未加入挑战的加入按钮
- **THEN** 系统持久化参与状态并显示当前进度

#### Scenario: 打开挑战详情
- **WHEN** 用户点击任一挑战卡
- **THEN** 系统展示规则、数据来源、当前进度、目标、完成比例和参与操作

#### Scenario: 浏览分层挑战目录
- **WHEN** 用户打开挑战页面并选择类别或难度
- **THEN** 系统展示匹配的挑战集合、层级名称和目标，不重复或随机改变已加入挑战的标识

### Requirement: 挑战进度计算

系统 SHALL 根据可用的真实 HealthKit 当日摘要和 Core Data 运动记录更新步数、距离或次数进度，不得用固定演示进度替代本地结果。

#### Scenario: 数据不足
- **WHEN** 计算挑战进度所需的健康权限或样本不可用
- **THEN** 系统保留挑战参与状态，将进度标记为暂无数据并提示需要的数据来源

#### Scenario: 真实数据可用
- **WHEN** 用户的健康摘要或本地运动记录可以支持挑战指标
- **THEN** 系统计算并展示来自这些本地真实数据的进度

### Requirement: 徽章与排行榜

系统 MUST 展示由本地真实健康与运动数据计算的已解锁和未解锁徽章；排行榜仅在后端提供正式接口时展示，当前无接口时 MUST 显示明确不可用状态且不得使用演示排名。

#### Scenario: 达成徽章条件
- **WHEN** 用户的真实运动数据首次满足徽章规则
- **THEN** 系统只解锁一次并记录解锁时间

#### Scenario: 排行榜接口缺失
- **WHEN** 用户打开排行榜且主后端未定义排行榜 API
- **THEN** 系统说明“当前后端未提供排行榜接口”，不显示模拟用户、排名或分数

### Requirement: 挑战目录可发现性

系统 MUST 提供搜索或筛选入口，使用户能够在不少于 60 条挑战中发现五公里、减脂、比赛、力量、骑行、步数和恢复等目标。

#### Scenario: 查找减脂五公里挑战
- **WHEN** 用户筛选跑步类别并搜索“减脂”
- **THEN** 系统展示匹配的减脂五公里挑战及其完成规则

### Requirement: 挑战行动视觉层级

系统 MUST 将挑战页面组织为当前进度、精选行动、筛选目录和成就状态，并为不同挑战类型使用可区分的健康语义色和进度表达。

#### Scenario: 用户浏览挑战
- **WHEN** 用户进入挑战 Tab
- **THEN** 用户能区分已参加挑战、可加入挑战、筛选条件和徽章状态，且不影响加入或退出操作
