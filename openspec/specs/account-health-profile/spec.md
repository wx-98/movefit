# 账户、健康与个人资料规格

## Purpose

定义账户入口、本地体验、个人资料、身体指标与账号控制的产品行为。

## Requirements

### Requirement: 账户入口与会话状态

系统 SHALL 使用主业务后端提供手机号或邮箱的密码注册和登录，并恢复安全会话；Apple ID 和微信仅在后端提供对应契约后启用，任何登录方式均不得模拟成功。

#### Scenario: 使用 Apple ID 登录
- **WHEN** 用户完成 Apple 授权且认证服务可用
- **THEN** 系统建立安全会话并进入主界面

#### Scenario: 远程认证未配置
- **WHEN** 用户选择需要服务端或第三方配置的登录方式
- **THEN** 系统展示明确的暂不可用说明，不得伪造真实登录成功

#### Scenario: 使用邮箱或手机号登录
- **WHEN** 用户提交合法标识符和密码且 `/auth/login/password` 返回令牌
- **THEN** 系统将令牌安全保存并读取当前用户资料后进入已登录状态

#### Scenario: 注册服务验证能力不可用
- **WHEN** `/auth/register` 因验证码供应商未配置返回不可用错误
- **THEN** 系统展示真实服务端错误和重试建议，不得回退为本地模拟账号

#### Scenario: 选择未提供的第三方登录
- **WHEN** 用户选择 Apple ID 或微信且当前主后端无对应 API
- **THEN** 系统展示“当前后端未提供对应接口”，不得建立本地模拟会话

### Requirement: 个人资料与身体指标

系统 MUST 在登录后读取服务端个人资料，并允许编辑头像、昵称、身高、体重、BMI 和体脂率；可由服务端保存的字段 MUST 使用 `base_version` 更新，健康专属本地字段 SHALL 保留明确单位和本地来源。

#### Scenario: 更新体重
- **WHEN** 用户提交合法体重值
- **THEN** 系统保存新值、重新计算 BMI，并刷新个人资料摘要

#### Scenario: 更新服务端资料
- **WHEN** 用户提交合法且服务端支持的资料字段
- **THEN** 系统使用当前版本发送 PATCH，成功后更新服务端版本与本地资料摘要

#### Scenario: 资料版本冲突
- **WHEN** 服务端返回版本冲突
- **THEN** 系统提示用户刷新资料后重试，不得覆盖较新的服务端数据

#### Scenario: 更新本地身体指标
- **WHEN** 用户提交合法体重值且该字段不在服务端契约内
- **THEN** 系统在本地保存带单位的值、重新计算 BMI，并明确其未同步到服务端

### Requirement: 设置与账号控制

系统 MUST 提供健康与设备、账号绑定、语言与外观、隐私政策、帮助支持、关于、退出登录和账号注销入口，并让每个入口进入可解释的详情状态。

#### Scenario: 退出登录
- **WHEN** 已登录用户确认退出
- **THEN** 系统清除安全会话，但保留符合数据所有权策略的本地运动记录

#### Scenario: 注销账号
- **WHEN** 远程服务未配置且用户选择注销账号
- **THEN** 系统说明无法提交远程注销，并提供仅清理本地可重建数据的独立操作

#### Scenario: 打开账号绑定
- **WHEN** 用户进入账号绑定页面
- **THEN** 系统分别展示 Apple ID 与微信的真实绑定状态或未配置要求

#### Scenario: 打开帮助与支持
- **WHEN** 用户进入帮助页面
- **THEN** 系统展示常见问题、权限排查、数据来源和版本信息入口

### Requirement: 个人中心完整摘要

系统 SHALL 展示真实个人指标、本地成就统计、已连接数据来源和设置分组；未填写或未授权的数据不得使用默认示例值。

#### Scenario: 首次打开个人中心
- **WHEN** 用户尚未填写资料且没有账号服务
- **THEN** 系统显示空指标、本地体验状态和可操作设置入口

### Requirement: 个人资料与设置视觉层级

系统 MUST 将我的页面组织为个人身份、身体指标、运动成就、账户与设备、隐私与支持分区，并使用可访问的原生设置行。

#### Scenario: 用户浏览设置
- **WHEN** 用户进入我的 Tab
- **THEN** 用户能从分区标题和图标识别资料、设备、隐私及帮助入口，且原有导航目的地保持不变
