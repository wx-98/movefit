## 背景

仓库当前没有 Xcode 工程或 Swift 源码，只有需求稿与五个 HTML 视觉参考。应用必须最低支持 iOS 15，遵守根目录 `AGENTS.md`，优先采用 Apple 原生框架，并在没有网络、HealthKit 未授权或位置权限受限时保持可用。

五个主界面固定为首页、挑战、运动、历史和我的。需求稿中的登录、健康录入、养护建议、运动会话等能力作为主界面的下钻流程实现，不额外增加主 Tab。

## 目标与非目标

### 目标

- 交付可在 Xcode 打开、构建和运行的 SwiftUI iOS 应用及测试 Target。
- 用统一设计系统复现参考页的信息层级、红/绿/蓝活动色和卡片式运动体验。
- 建立 `View -> ViewModel -> UseCase -> Repository` 的依赖边界。
- 使用 HealthKit、CoreLocation、Core Data、Keychain 等原生能力并提供可测试替身。
- 以本地优先方式覆盖五个主页面和关键下钻流程。

### 非目标

- 本次不交付独立服务端、运营后台、微信开放平台配置或真实排行榜服务。
- 本次不实现付费、多语言、社交分享和第三方硬件 SDK。
- 健康建议不构成医疗诊断，不提供临床阈值或治疗决策。
- 不逐像素照搬 Keep、Apple 健康或参考 HTML 的受保护素材。

## 技术决策

### 1. 使用单 App Target 加按层目录组织

首版采用一个应用 Target、一个单元测试 Target 和一个 UI 测试 Target。代码按 `App`、`Features`、`Domain`、`Data`、`Platform`、`DesignSystem` 分组；只有当模块需要独立复用或编译隔离时才拆 Swift Package。

选择原因：当前项目从零开始，先建立清晰边界比立即引入多 Target 依赖图更容易维护。备选的完全模块化方案会显著增加工程配置和跨模块访问控制成本。

### 2. SwiftUI 使用 MVVM 与用例层

ViewModel 统一标记 `@MainActor`，以不可变 `ViewState` 驱动页面。View 只发送语义事件；业务逻辑由 UseCase 调用 Repository Protocol 完成。平台实现通过 App 入口组合并以初始化器注入。

选择原因：该结构符合项目 Rule，能隔离 HealthKit、Core Data 和位置 API，也便于使用内存实现进行测试。首版不引入第三方状态管理框架。

### 3. 本地优先并区分数据所有权

- HealthKit 是步数、心率、活动能量和用户授权健康样本的外部事实来源。
- Core Data 保存 App 自有运动、收藏、挑战状态、缓存摘要和同步操作。
- Keychain 保存访问令牌或未来服务端凭据。
- 远程账号、挑战和内容通过协议预留；无服务端配置时使用内置演示仓库，页面明确展示本地演示数据。

避免把 HealthKit 查询无结果推断为拒绝权限。所有离线写操作具有稳定 ID，未来连接服务端时可幂等提交。

### 4. 运动会话使用显式状态机

运动会话状态为 `idle -> preparing -> running <-> paused -> ending -> saving -> completed`，失败状态保留可恢复信息。户外运动由位置适配器提供路线点；室内运动不强制请求位置权限。计时使用单调时钟语义，避免系统时间变化导致时长错误。

### 5. iOS 15 兼容策略

- 本地数据库使用 Core Data，不使用 SwiftData。
- 图表使用 SwiftUI `Shape`/布局组件，不依赖仅支持更高系统版本的 Swift Charts。
- 导航使用 iOS 15 可用的 `NavigationView` 封装；高版本优化必须提供降级实现。
- 异步接口使用 `async/await`，平台回调在 Adapter 内转换。

### 6. 设计系统与品牌资源

参考 HTML 中重复的颜色、字体、间距、圆角和阴影转为语义 Token。界面图标使用 SF Symbols；远程示例图片不得成为运行时依赖。产品显示名称统一为 MoveFit，默认界面语言为中文，单位根据 Locale 展示，中文环境默认公制。

现有 1024×1024 Logo 作为设计源导入资源目录；应用图标输出必须全幅、无意外透明边缘，并由系统负责圆角裁切。

### 7. 测试与可替换平台适配器

HealthKit、位置、时间、UUID、账户和持久化均通过协议注入。单元测试覆盖聚合、状态机、格式化和推荐规则；Core Data 使用内存 Store；UI 测试通过启动参数切换演示数据、无权限和离线状态。

## 风险与权衡

- **没有服务端配置，真实注册、微信登录和全球排行榜无法完成** → 首版提供协议、校验流程和演示仓库，接入前必须创建单独 OpenSpec change。
- **HealthKit 真机行为无法由模拟器完整验证** → 以 Fake 做自动化测试，并保留真机验收清单。
- **后台定位耗电且可能被系统终止** → 仅在户外会话期间启用，持久化会话快照并支持恢复。
- **健康建议可能被误解为医疗建议** → 使用低风险生活方式规则，展示免责声明，不根据单次异常数据给出诊断。
- **五页参考与需求范围不完全一致** → 五个 Tab 保持不变，缺失能力通过首页、运动和我的页面下钻承载。
- **从零一次性交付范围较大** → 任务按工程基础、领域/数据、五个 Feature、测试和验收分段，每段均保持可构建。

## 迁移与回滚

1. 新增 Xcode 工程、资源和基础分层，不改动现有需求稿与参考文件。
2. 先接入演示仓库保证五个 Tab 可运行，再接入 Core Data 与平台能力。
3. 平台权限按用户触发逐项申请，未授权时保持演示或手动录入路径。
4. 如某平台集成导致构建失败，可在 App 组合层切回内存实现，不影响 Feature UI。
