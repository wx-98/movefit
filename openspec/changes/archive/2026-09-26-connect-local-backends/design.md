## Context

MoveFit 已完成 SwiftUI、Core Data、HealthKit 与本地内容层，但账户仍由 `LocalAuthenticationAdapter` 模拟，资料和运动记录未接主后端，动作库只读取 Bundle。现有两个本地服务分别提供主业务 API（8000）和动作目录 API（8001），且动作服务文档与运行时 OpenAPI 的分页参数存在差异。

必须继续遵守 `View -> ViewModel -> UseCase -> Repository Protocol -> Repository Implementation`、初始化器注入、HealthKit 边界和 iOS 15 基线。服务端 DTO、令牌和错误不得进入 View 或 Domain。

## Goals / Non-Goals

**Goals:**

- 真实接入当前服务已经定义的认证、资料、运动、同步、客户端配置和动作目录接口。
- 将两个服务地址集中为可按构建配置覆盖的设置，Debug 默认可直接连接本机。
- 安全保存会话、处理一次令牌刷新、映射可判别错误，并支持 URLSession 测试替身。
- 服务不可达时保留本地健康和运动能力，但明确区分“远程失败”“后端未提供”和“本地降级”。
- 提供完整中文接入与上线切换文档。

**Non-Goals:**

- 不发明 Apple/微信 OAuth、账号绑定、排行榜、挑战目录、文章、工单或账号注销接口。
- 不批量上传 HealthKit 原始样本或路线等敏感信息。
- 不引入第三方网络、缓存或图片依赖。
- 不改变后端契约或代替后端实现缺失能力。

## Decisions

### 1. 使用构建设置注入双服务地址

Info.plist 保存由 Xcode Build Settings 替换的主服务与动作服务地址。Debug 默认值为 `http://127.0.0.1:8000` 和 `http://127.0.0.1:8001`；Release 使用独立变量且上线前必须覆盖为 HTTPS。`AppEnvironment` 负责校验和生成 URL，业务代码不得硬编码主机地址。

相较于在 Repository 内拼接常量，此方案能让模拟器、真机、测试和生产环境切换不改 Swift 代码；相较于运行时可编辑地址，构建注入不会把内部环境开关暴露给普通用户。

### 2. 一个主 API Client，多组领域 Repository

`MoveFitAPIClient` 统一处理 URLRequest、JSON、Bearer、刷新、Problem Details 和幂等键；认证、资料、运动、配置分别通过领域协议暴露。动作服务使用独立 `RemoteExerciseCatalogRepository`，避免两个服务的契约和错误模型混杂。

URLSession 与会话存储均通过初始化器注入，单元测试使用自定义 `URLProtocol`，不依赖正在运行的本地服务。真实服务另设可重复执行的连通性脚本/命令。

### 3. Keychain 持久化令牌，401 最多刷新一次

访问令牌、刷新令牌和当前账户摘要只写入 Keychain。受保护请求收到 401 后，Client 使用刷新令牌调用 `/auth/token/refresh`，更新旋转后的令牌并重放原请求一次；再次失败即清除会话并返回未认证错误，防止无限重试。

日志不得输出凭据、健康数据或完整响应正文。

### 4. 远程数据映射后再进入 Domain

网络 DTO 留在 Data/Networking 层。日期使用兼容小数秒的 ISO 8601 策略；运动类型和来源显式映射，未知枚举值作为可判别映射错误处理。距离、热量继续转换为带单位的领域值。

主后端只接受 running、walking、cycling、yoga、strength、hiit。其他本地类型继续保存在 Core Data，并在同步状态中说明“不受当前服务端枚举支持”，不改变用户本地保存结果。

### 5. 本地优先保存，认证后同步 MoveFit 记录

运动结束或手动录入先写 Core Data，成功后再尝试上传；远程失败不回滚本地记录。登录/恢复会话后分页读取服务端运动，并与本地、HealthKit 记录按稳定 ID 和来源合并。HealthKit 导入记录只从服务端读取已有数据，本次客户端不自动上传设备 HealthKit 样本。

个人资料在登录后从 `/me` 读取；编辑时先验证，再用 `base_version` 乐观锁 PATCH，成功后更新本地缓存。409/412 明确提示刷新后重试。

### 6. 动作目录使用远程优先、本地明确降级

动作请求使用运行时 OpenAPI 确认的 `page_size`，支持搜索、器械、肌群、难度和分页。DTO 显式映射中文难度、动作步骤、安全提示和图片 URL。首次加载失败时读取 `BundledExerciseCatalog`，界面显示“内置降级内容”，不得显示已远程同步。

### 7. 缺失接口统一展示能力边界

Apple/微信入口、排行榜等现有界面不执行模拟成功。它们显示“当前后端未提供对应 API”，并可保留本地可完成的挑战参与、徽章和健康能力。这样既不删除已完成的本地产品体验，也不把本地逻辑误称为服务端数据。

## Risks / Trade-offs

- [本地 HTTP 在真机不可直接使用 127.0.0.1] → 文档要求真机改为开发机局域网地址，并仅在开发构建允许本地网络；生产强制 HTTPS。
- [访问令牌刷新并发导致重复旋转] → API Client 串行化刷新任务，让并发 401 共享同一次刷新结果。
- [服务端注册依赖验证码供应商，可能返回 503] → 保留真实错误并解释服务端验证能力未配置，不回退为模拟注册。
- [本地与服务端数据重复] → 客户端生成并复用 UUID 作为服务端记录 ID，合并时使用稳定 ID 和来源。
- [两份现有后端文档与运行时契约漂移] → 实现和集成测试以运行时 OpenAPI 为最终依据，并记录发现的 `page_size` 差异。
- [远程失败影响启动体验] → 各远程加载独立失败，本地 Core Data、HealthKit 和内置动作目录仍可使用，并显示来源状态。

## Migration Plan

1. 增加环境、会话、API Client 和 DTO 映射，保持现有本地实现可回退。
2. 将 App 依赖装配切换为真实 Repository，并逐项接入认证、资料、运动、配置与动作目录。
3. 移除模拟登录与演示排行榜成功路径，补充缺失 API 状态。
4. 运行单元测试、UI 测试、构建测试及两个本地服务的连通性验证。
5. 发布前在 Release 构建配置中设置 HTTPS 地址，并验证服务器证书、隐私声明和真实设备网络。

回滚时可将依赖装配恢复为纯本地 Repository；不得恢复模拟认证或把本地数据标成远程数据。
