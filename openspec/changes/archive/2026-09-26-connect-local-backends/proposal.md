## Why

MoveFit 当前仍使用本地模拟登录、仅本地保存的资料与运动记录，以及内置动作目录，无法验证已部署后端的真实行为。现在两个本地服务均已可访问，需要建立可配置、可测试且适合后续上线切换的真实接口边界，并彻底停止伪造服务端成功状态。

## What Changes

- 增加集中式环境配置，分别管理主业务后端与动作目录服务的地址，Debug 默认连接本机服务，Release 可通过构建配置覆盖。
- 接入主业务后端的密码注册、登录、令牌刷新、退出、个人资料、运动记录、增量同步和客户端配置接口。
- 使用 Keychain 保存访问令牌与刷新令牌；遇到未授权响应时仅自动刷新一次，并提供明确错误状态。
- 将动作目录切换为 `GET /v1/exercises` 的真实数据，按运行时 OpenAPI 使用 `page_size`，远程失败时保留明确标识的内置降级内容。
- 停止本地模拟登录和演示排行榜；后端未提供 Apple、微信、排行榜、挑战目录、帮助工单等接口时，界面明确说明该能力尚无服务端 API，不虚构请求路径或成功结果。
- 将本地 MoveFit 运动记录与服务端记录同步；HealthKit 数据继续直接来自设备，未经用户主动创建或现有隐私策略授权不批量上传。
- 补充中文配置、接口映射、测试和上线切换说明。

## Capabilities

### New Capabilities

- `backend-environment`: 定义双后端地址配置、连通性、错误模型、令牌刷新和测试/上线切换行为。
- `backend-exercise-catalog`: 定义真实动作目录的分页、过滤、DTO 映射与本地降级行为。

### Modified Capabilities

- `account-health-profile`: 手机号/邮箱改为真实密码认证，登录后读取和更新服务端个人资料；未提供的第三方认证不得模拟成功。
- `workout-management`: MoveFit 创建及手动录入的受支持运动类型写入服务端，并读取、分页合并服务端运动记录。
- `challenges-achievements`: 移除排行榜演示数据；后端未提供排行榜接口时仅展示明确的不可用状态。

## Impact

- 影响 App 依赖装配、账户、个人资料、运动保存与历史加载、动作目录、挑战排行榜和设置状态界面。
- 新增 URLSession API Client、DTO/映射、Keychain 会话存储和环境配置；不新增第三方依赖。
- 对接 `http://127.0.0.1:8000/api/v1` 与 `http://127.0.0.1:8001/v1`；本地 HTTP 仅用于开发，上线必须改为 HTTPS。
- 服务端当前未提供 Apple/微信登录绑定、排行榜、挑战目录、文章内容和帮助工单接口，这些能力不在本次真实接入范围内，也不得继续使用模拟服务端数据。
