## MODIFIED Requirements

### Requirement: 账户入口与会话状态
系统 SHALL 使用主业务后端提供手机号或邮箱的密码注册和登录，并恢复安全会话；Apple ID 和微信仅在后端提供对应契约后启用，任何登录方式均不得模拟成功。

#### Scenario: 使用邮箱或手机号登录
- **WHEN** 用户提交合法标识符和密码且 `/auth/login/password` 返回令牌
- **THEN** 系统将令牌安全保存并读取当前用户资料后进入已登录状态

#### Scenario: 注册服务验证能力不可用
- **WHEN** `/auth/register` 因验证码供应商未配置返回不可用错误
- **THEN** 系统展示真实服务端错误和重试建议，不得回退为本地模拟账号

#### Scenario: 选择未提供的第三方登录
- **WHEN** 用户选择 Apple ID 或微信且当前主后端无对应 API
- **THEN** 系统展示“当前后端未提供对应接口”，不得建立本地模拟会话

### Requirement: 个人资料与身体指标
系统 MUST 在登录后读取服务端个人资料，并允许编辑头像、昵称、身高、体重、BMI 和体脂率；可由服务端保存的字段 MUST 使用 `base_version` 更新，健康专属本地字段 SHALL 保留明确单位和本地来源。

#### Scenario: 更新服务端资料
- **WHEN** 用户提交合法且服务端支持的资料字段
- **THEN** 系统使用当前版本发送 PATCH，成功后更新服务端版本与本地资料摘要

#### Scenario: 资料版本冲突
- **WHEN** 服务端返回版本冲突
- **THEN** 系统提示用户刷新资料后重试，不得覆盖较新的服务端数据

#### Scenario: 更新本地身体指标
- **WHEN** 用户提交合法体重值且该字段不在服务端契约内
- **THEN** 系统在本地保存带单位的值、重新计算 BMI，并明确其未同步到服务端
