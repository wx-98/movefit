# MoveFit 动作目录后端接入说明

## 当前状态

生产 App 当前注入 `BundledExerciseCatalog`，提供少量已中文化、补充安全提示的离线动作。App 不直接请求 GitHub Raw，也不把上游 JSON DTO 暴露给 View 或 Domain。

`wrkout/exercises.json` 仓库使用 Unlicense，可作为动作结构与文字的候选来源。但上线前仍需逐条中文化、去重、安全审核，并单独确认图片、视频等媒体的实际许可。上游仓库不可用时不得影响 App 的本地动作库。

## 客户端接口

```swift
protocol ExerciseCatalogProviding {
    func exercises(
        query: ExerciseCatalogQuery,
        page: Int,
        pageSize: Int
    ) async throws -> ExerciseCatalogPage
}
```

查询支持：

- 文本搜索；
- 器械过滤；
- 主要肌群过滤；
- 入门、进阶、高阶难度过滤；
- 分页和 `hasMore`。

客户端领域模型只接收稳定 ID、中文名、原名、难度、器械、肌群、步骤、安全提示和内容版本。

## 建议服务端 API

GET /v1/exercises?q=&equipment=&muscle=&difficulty=&page=0&pageSize=20

## 发布管线要求

1. 服务端固定上游 commit 或发布版本，禁止运行时透传 GitHub `master`。
2. 以稳定 ID 去重，并记录来源版本、审核版本和发布时间。
3. 人工审核中文动作名、器械、肌群、步骤和安全提示。
4. 过滤危险、含糊或无法验证的指导；所有详情保留“疼痛时立即停止”声明。
5. 动作图片和视频必须保存独立许可与署名信息；无明确许可时不分发。
6. API 使用 HTTPS、超时、缓存和可判别错误；失败时客户端回退到本地动作。
7. 服务端不得接收 HealthKit 样本、身体指标或精确位置来完成普通目录查询。

## 客户端接入步骤

1. 在 Data 层新增版本化远程 DTO 与映射器。
2. 实现 `RemoteExerciseCatalogRepository`，不修改 View。
3. 在 App 入口通过初始化器替换 `BundledExerciseCatalog`。
4. 保留本地回退和“数据来源版本”展示。
5. 增加 DTO 映射、分页、过滤、超时、离线回退和错误状态测试。
